# 基本用語集

まず覚えるべき語を、UIレビューで使いやすい意味に絞って整理します。

| 用語 | 意味 | レビューでの見方 |
|---|---|---|
| 視覚的階層 | 重要度が見た目の強弱として表現されること | 最初に見る場所は意図どおりか |
| フォーカルポイント | 最初に視線を集める場所 | 主役が一目で分かるか |
| 視覚的ウェイト | 要素が感じさせる「重さ」 | 一部だけ不自然に重くないか |
| ネガティブスペース | 要素そのものではない空間 | 空白が主役を支えているか |
| 情報密度 | 一定領域に含まれる情報量 | 詰め込みすぎていないか |
| 近接 | 近いものを同じグループと認識する性質 | 関係ない要素が近すぎないか |
| 類同 | 似た見た目を同種と認識する性質 | 同じ役割に同じ表現が使われているか |
| 図と地 | 主役と背景を分けて知覚すること | 主役が背景へ埋もれていないか |
| 整列 | 共通の基準線に要素を揃えること | 揃える基準が一貫しているか |
| グリッド | 配置を支える見えない構造 | 要素が場当たり的に置かれていないか |
| バランス | 画面全体の視覚的な安定 | 左右・上下の重さが意図どおりか |
| リズム | 反復と変化による視覚的な流れ | 単調すぎる／乱雑すぎないか |
| コントラスト | 差によって区別や強調を作ること | 重要度の差が十分か |
| タイポグラフィ | 文字の形・大きさ・間隔・行構成 | 「収まる」だけで終わっていないか |
| 行長 | 1行の文字列の長さ | 長すぎて追いにくくないか |
| 行間 | 行と行の間隔 | 密集／分断して見えないか |
| アフォーダンス | どう操作できるかを推測させる性質 | ボタンが押せそうに見えるか |
| シグニファイア | 操作方法を示す手掛かり | アイコンや形が操作を伝えているか |
| フィードバック | 操作結果を利用者へ返すこと | 押した結果が分かるか |
| ヒットエリア | 実際に操作を受け付ける領域 | 見た目と押せる範囲が不自然でないか |
| レスポンシブ | 画面条件に応じて構成を適応すること | 小画面化で何を守っているか |
| リフロー | 要素が利用可能幅に応じて再配置されること | 単なる縮小になっていないか |
| 制約 | 変更してよい範囲を決める条件 | AIが勝手に構成変更できないようにする |
| 不変条件 | 変更後も必ず保持する性質 | 原案の何を絶対に守るか |
| 紙プロトタイプ | 紙や手描きで画面構造・配置・操作を検討する試作 | ラフではなく視覚仕様書として十分に詰められているか |
| 静的UI契約 | 完成状態の位置・比率・余白などを実装前に合意した仕様 | 実装段階に不要なデザイン判断が残っていないか |
| 契約実装 | 完成見本や不変条件を「改善」せず再現する実装方針 | 実装者が勝手に均等化・拡張していないか |
| visual bounds | 利用者に見えている要素の視覚領域 | 操作性のために見た目まで広げていないか |
| hit bounds | タップやクリックを受け付ける操作領域 | 十分な広さを持ちつつ他領域と衝突していないか |
| 状態 (state) | UIが意味上どの状況にあるかを表す値 | 見た目と論理状態が一致しているか |
| 遷移 (transition) | ある状態から別の状態へ移ること | 開始・終了・中断条件が定義されているか |
| 進捗 (progress) | 遷移途中の連続的な位置 | stateと混同していないか |
| キーフレーム | 動きの途中で重要となる基準状態 | 全フレームを描かず重要点を定義できているか |
| SceneState | 複数要素が同時に意味を変えるシーン全体の状態 | 個別booleanの不正な組み合わせを防げているか |
| 演出レイヤー | 機能に必須でない動きや視覚効果を本体UIから分離した層 | 停止しても操作・情報理解が成立するか |
