# Design FE

**エンジニアのためのデザイン基本情報**

「なんか変」を、説明して直せるようになるためのデザイン基礎カリキュラムです。

デザイナーになることが目的ではありません。  
UIを見たときに違和感の原因を切り分け、デザイン上の意図を守りながら、AIやフロントエンド実装へ正確に指示できる状態を目指します。

> エンジニアが「動く・収まる・壊れない」を判断できるように、  
> デザインでも「なぜ見づらいのか」「なぜ主役が埋もれるのか」を判断できる語彙を持つ。

## 対象

- UIを作るエンジニア
- AIコーディングで画面を作る人
- デザイナーとの会話で「なんとなく」を減らしたい人
- Figmaの完成見本を実装へ正確に落としたい人
- デザインを専門職にするつもりはないが、良し悪しを判定できるようになりたい人

HTML/CSSやFigmaの操作経験は必須ではありません。

## 到達目標

学習後、次のような変換が自然にできる状態を目指します。

**Before**

> キャラが埋もれている。もう少し目立たせて。

**After**

> 左側のネガティブスペースが減り、キャラクターと選択肢の図と地の分離が弱くなっている。  
> キャラクター自体を拡大するのではなく、原案の余白と視覚的階層を戻す。

そしてAIには、

> 見やすく改善してください。

ではなく、

> 原案のネガティブスペース、視覚的階層、キャラクターの視覚的優位性を維持してください。  
> 局所的な文字収まりを理由に全体構成を変更しないでください。

と指示できるようになることを狙います。

## カリキュラム

| # | 分野 | 主なキーワード |
|---|---|---|
| 01 | 視覚的階層 | hierarchy, emphasis, focal point, visual weight |
| 02 | 余白 | whitespace, negative space, density |
| 03 | ゲシュタルト | proximity, similarity, closure, figure-ground |
| 04 | 整列とグリッド | alignment, grid, balance, rhythm |
| 05 | タイポグラフィ | hierarchy, line-height, measure, weight |
| 06 | 色 | contrast, hue, saturation, value, harmony |
| 07 | 操作性 | affordance, signifier, feedback, target size |
| 08 | レスポンシブ | priority, reflow, constraints, preservation |
| 09 | UIレビュー | observation, diagnosis, cause, correction |
| 10 | AIへの指示 | constraints, invariants, reference fidelity |

詳細は [docs/curriculum.md](docs/curriculum.md) を参照してください。

## 学び方

各章は原則として次の順序で読みます。

1. 用語を知る
2. 原理を理解する
3. 悪い例の「何が悪いか」を言語化する
4. 修正案を考える
5. AIへの指示文へ変換する
6. 実際のUIで診断する

暗記よりも、**見た瞬間に概念が浮かぶこと**を重視します。

## 午後問題

知識問題だけではなく、スクリーンショット比較型の演習を用意します。

例：

> 左図から右図への変更で、案内役の存在感が低下した。  
> 関連するデザイン原則を2つ挙げ、原因と修正方針を100字程度で説明せよ。

## このリポジトリで扱わないこと

- イラストを上手に描く技術
- Figmaの操作方法そのもの
- 流行のUIテンプレート集
- 「この数値にすれば必ず美しい」という万能ルール
- デザイナーという専門職の代替

デザイン原則には文脈依存があります。  
この教材は、ルールを機械的に適用するためではなく、**意図を読み、差分を説明するための判断材料**として扱います。
